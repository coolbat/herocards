# 卡片生成分析与首批魔兽全幅卡改进

日期：2026-09-07。范围：本地 cardcreat 工作区，未提交、未发布。

## 结论

主要瓶颈同时存在于原画、贴图派生和显示层。原先 24 位英雄只有希尔瓦娜斯使用全幅原画；魔兽详情页虽然调用四贴图生成管线，实际只用 2D canvas 绘制 diffuse，悬停高光来自 CSS。现已新增吉安娜、萨尔、阿尔萨斯、伊利丹四套原画、深度图及成卡缩略图，并让详情页使用真实 WebGL 光照。全幅卡现为 5/24，另外 19 位仍使用原肖像。

## 已落实的改进

| 问题 | 本次处理 | 证据位置 |
|---|---|---|
| 统一裁底部 8%，没有适配各卡构图 | 逐卡设置 `fullArtCropBottom`；三张新卡为 0，吉安娜为适应固定称号区域使用 0.20；原画与深度图共用同一变换 | `js/card-art.js` / `js/heroes-data-wow.js` |
| 新卡装饰布局与希尔瓦娜斯基准不一致 | 按用户网页反馈，撤回 compact 试验；四卡与希尔瓦娜斯共用铭牌、称号、绶带、三属性圆章与双徽章的默认路径 | `card-art.js` / 同款五卡预览 |
| 所有英雄默认用希尔瓦娜斯的 17 个禁区 | 四卡各自设置脸部、场景、地面的禁区；非圆形光源关闭月环拟合 | 英雄数据 `goldLineParams` |

## 同源对比结果

以下保留首次 compact 试验阶段的测量记录，最终布局已按用户要求切回希尔瓦娜斯基准；当前读数以文末样式统一记录及 `production/wow-imagegen/*-qc.json` 为准。该次旧值与新值使用同一原画、同一 v2 深度图；旧值为默认裁剪、旧布局、希尔瓦娜斯默认金线参数、无新增深度平滑，不是旧肖像与新原画的混合比较。统计沿用 `test/fullart-test.html` 的计算口径。

| 英雄 | 法线活跃均值：旧 → 新 | 新版粗糙度中间档 | 金线连通域 | 渲染耗时 |
|---|---:|---:|---:|---:|
| 吉安娜 | 43.99 → 28.74 | 62.02% | 20 | 670 ms |
| 萨尔 | 47.94 → 32.00 | 61.10% | 27 | 694 ms |
| 阿尔萨斯 | 33.24 → 23.05 | 55.32% | 23 | 691 ms |
| 伊利丹 | 49.84 → 29.65 | 65.19% | 20 | 656 ms |

四卡均达到既有法线活跃均值 22–40、粗糙度中间档 ≥45%、金线连通域 ≤30 的检查条件。左上光与默认光的红通道平均像素差为 14.7–15.5（0–255 量纲），说明显示确实响应光源变化。耗时是本机单次观测，不是所有设备的保证。

高度梯度并非所有读数都达标：萨尔 p50=0，另外三卡为 1.5/1.5/2；四卡 p99=388–408，明显高于老参考图的 64–77。宏观深度平面、金线和新铭牌边缘影响该指标；本次通过三光位和原生像素截图接受这批视觉结果，并保留异常读数，不把它们表述为全指标通过。后续可继续细化连续深度体积与材质边界。

## 美术与数据边界

- 原画和深度图均由用户确认的内置 ImageGen 生成。每幅 1024×1536，未获得原生 4K；虽然编码不放大，1329×2048 渲染贴图仍会放大采样，不能宣称解决所有高清输出需求。
- 语义深度图已目检人物、装备与远景的相对层级及主要轮廓，但不是经过几何标定的真实深度，也不承诺逐像素精确对齐。
- 阿尔萨斯使用未戴统御之盔的死亡骑士造型；萨尔使用毁灭之锤黑甲时期；原有英雄传记和称号继续沿用。
- 新四卡的运行图、深度图、缩略图合计约 3.15 MiB。PNG 母版保存在 `assets/portraits/wow-masters/`，不进入展示站或小工具运行包。
- 未更改国风主站的 shader 参数、既有图像编码策略或四套 LRU 缓存上限。共享管线的新行为均由新卡字段启用。

## 复现与继续生产

1. 按 `production/wow-imagegen-v1.json` 的实际提示词，用内置 ImageGen 生成原画；输出留档到 wow-masters。原画不附风格参考图。
2. 以该原画为唯一输入生成 v2 技术深度图；拒绝带摄影光照、材质纹理或重新构图的高度图。
3. `python3 production/build-wow-runtime.py`；指定 hero id 可分批编码。清单保留源文件及运行文件 SHA-256。
4. 打开 `test/wow-qc.html?hero=<id>`，检查旧/新对比、三光位、脸部原生像素、四贴图、场景碎金。按图维护禁区。
5. 在该工作区本地站打开后执行 `playwright-cli run-code --filename=production/bake-wow-thumbs.cjs`，导出审核成卡缩略图和 QC JSON；修改原画、布局或字体后必须重新导出。
6. `npm run check`，再执行 `playwright-cli run-code --filename=test/verify-wow-browser.cjs` 与 `npm run build:pages`。

逐卡 JSON：`production/wow-imagegen/*-qc.json`。原画/深度及运行清单：`production/wow-runtime-manifest.json`。截图：`output/playwright/*-qc.png`。

## 网页清晰度复查与修正

用户在网页体验后反馈模糊。初次验收对交互、材质和资源完整性的检查，未充分覆盖最终显示尺寸的清晰度，不能据此判断画质已达标。

在同一 310×478 CSS px、无倾斜的对照中，原图 PNG 与成卡 diffuse 保留了明显更多的发丝、衣料纹理和铭牌细线；原 WebGL 输出明显偏软。原图为 1024×1536、成卡纹理为 1329×2048、1 倍屏幕上的原 WebGL 缓冲为 310×478。将缓冲单独提高到 620×956 只有部分改善；进一步让 diffuse 直接线性采样完整纹理后，文字与细节明显恢复。因此本次网页小尺寸模糊主要发生在光照纹理采样与最终绘制链路，不能简单归结为原画分辨率不足。

- diffuse 不再混合自动生成的多级缩小纹理；normal、rough、height 继续用 mipmap，保留光照稳定性。
- 详情绘制至少使用 2 倍采样，上限 2.5；使用未倾斜的布局尺寸计算缓冲，避免鼠标倾斜引起尺寸变化和重新分配。
- 卡墙从固定 300px 缓冲改为按显示宽度和 DPR 绘制，上限 640px。四张已烘焙缩略图仍只有原生 400px，不能靠画布扩大增加其真实细节。
- 实测桌面缓冲 620×956，移动鼠标后缓冲尺寸保持不变；手机 DPR 3 仍为 775×1195。五张全幅卡、鼠标响应、上下文恢复、减少动画、2D 回退均通过，无页面运行错误。26 项检查通过。

对照页面：`output/playwright/clarity-compare.html`（保存了修正前渲染器，只作本地诊断）。图像证据：`clarity-compare.png`（原图、底图、1 倍、仅 2 倍采样）、`clarity-sampling.png`（最后一列进一步直接采样 diffuse）。新版实际网页截图仍为 `wow-desktop-jaina.png` 和 `wow-mobile-390-dpr3.png`。显示修正不会增加原画真实细节；1024×1536 的原生分辨率仍限制高倍率放大和大尺寸导出。

## 最终样式统一：以希尔瓦娜斯为基准

用户明确要求卡片样式先按照希尔瓦娜斯实施。四张 ImageGen 卡现共用希尔瓦娜斯的默认装饰路径：顶部弧形铭牌、称号饰线、稀有度绶带、三枚属性圆章、底部双徽章与金框。compact 分支及其数据字段已移除；采样清晰度修正继续保留。

吉安娜原画的头部位置偏高，直接套用固定模板会使称号与其暗底遮住额头。最终将她的 `fullArtCropBottom` 设为 0.20，扩大取景并将脸部下移到称号暗底以下；这会裁去原画下方地面和部分靴部。原画文件保持不变，色彩与深度共用该变换，五个金线禁区已同步调整坐标。其他三卡保持 0 裁剪。
